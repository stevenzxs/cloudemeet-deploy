# 在线发布材料使用本批 origin/TLS 契约

## 意图

修复联合构建中在线材料组装因 `config/client.env` 缺少 `SITE_PORT` 等部署期字段而失败的问题，并确保生成的客户端配置对应本次 Run 实际核验的目标。

## 目标与非目标

- 在线材料组装应使用本次 Run 已核验的 origin 和 TLS 契约生成客户端部署配置。
- 缺少、非法或与已核验契约冲突的输入应明确失败，不得使用隐式默认值掩盖问题。
- `config/client.env` 继续只承载静态客户端字段，例如客户端版本和 CA 文件。
- 不重跑构建、不发布、不部署；不复用已消耗的版本 `11248.0.1+r54`。

## 方案

1. **推荐并选定：显式传递本次 Run 契约。** 联合构建流程将已核验的 origin/TLS 契约传入 `online-material.py`；生成器据此产生客户端配置并校验输入。动态配置以本批契约为准，避免与静态配置漂移。
2. **未选：补全静态 `config/client.env`。** 虽然改动较小，但会重复保存部署参数，且未来运行参数变化时容易不一致。

## 测试与验收

- 回归测试使用当前不含 `SITE_PORT`、`SITE_SCHEME`、`SITE_DOMAIN`、`TLS_MODE` 的 `client.env`，验证在线材料组装成功，并且输出 origin/TLS 与传入的已核验契约一致。
- 覆盖契约缺失或非法时明确失败。
- 运行相关测试及仓库要求的测试集；完成后按项目流程提交、合入并推送 `main`。

## 实施边界

实现者负责确认联合构建步骤中已核验契约的真实来源与传递方式，避免从未经核验的用户输入或环境变量重新拼装信任边界。该修复不授权触发新的联合构建/发布 Run，也不授权部署。
