# 首次 Docker 部署技能设计

## 意图
在 `skills/first-install/` 新建一个可独立使用的技能，指导首次在 Linux 服务器上通过 Docker 部署 CloudMeet 八个服务。用户已确认技能不得依赖其他目录。

## 目标与边界
- 目标：自包含的最小技能包，覆盖必要的首次安装说明、脚本、模板及非秘密默认配置，并在安全前提不足时停止。
- 八个服务：`web`、`app-web`、`api`、`jitsi-mgr`、`gateway`、`prosody`、`jicofo`、`jvb`。
- 不做构建/发布、版本分配、客户端、升级、离线包，也不连接/改动服务器来创建技能。
- 禁止引用或运行 `skills/full-build-deploy`、其他 `skills/*` 或外部技能目录内的文件；运行所需材料必须在 `skills/first-install/` 内。

## 方案
1. 仅写说明并指向现有脚本：最少文件，但违反自包含要求，排除。
2. 迁入首次安装必要的实现和配置，剔除升级、构建、发布等内容：推荐，兼顾独立性与最小范围。
3. 整套迁移部署运行时：可覆盖更多操作，但超出首次安装需求。

## 约束与验收
- 参考 `skills/msi-build-deploy/SKILL.md` 的结构：frontmatter、范围/授权、固定契约、操作步骤、停止条件。
- 测试新技能引用的本地依赖完整，且没有指向其他技能目录的路径；运行与技能实现相关的现有测试。
- 不启动真实部署。文档和脚本的最终细节由实现阶段依据被检查的运行时依赖决定。
