# CloudMeet 交互式部署技能

目录约定（2026-11-11）：仅从 `deploy/release/<amd64|aarch64>/{server,clients,dependencies}/` 交付；`deploy/config/` 为公共配置目标。未完成候选留在Actions临时工作区及有期限artifact，不下载到本地交付树，不通过改状态或改目录放行。用户已授权删除 `deploy/debug/` 全部内容、不迁移其中材料；不得重建。其他旧材料不在删除范围，工具输出尚未全面适配。完整规范仅由 deploy/AGENTS.md 负责。

按 **收集部署参数 → 解释服务和补丁 → 用户确认方案 → 逐服务部署并报告进度 → 关键测试及结果报告** 执行。历史实例只是排坑证据，不是默认地址、平台或部署方案。本次仅要求编写文档/计划时不连接或部署。

## 0. 工作区入口与执行边界

编译、打包、部署的唯一规范源为 `deploy/AGENTS.md`，完整要求均在该文件。本技能及后续 references 仅提供操作方法、示例和排坑资料，不新增或覆盖规范；入口登记和 README 只提供实现清单与材料导航。

执行规范完整集中在 `deploy/AGENTS.md`；根 AGENTS 的环境保护要求仍遵守，README 仅导航材料，无需靠其他文档补全规范。维护源 `deploy/skills/cloudmeet-deploy/`，安装副本同步使用。
交付按产物自身架构使用 `amd64` 或 `aarch64`，不是按客户端连接的服务器分类：合格服务器包进 `deploy/release/<架构>/server/<批次>/`，客户端进同级 `clients/<批次>/`，Docker/Compose等依赖进 `dependencies/<OS及版本>/<组件版本>/`。服务器包附INSTALL、摘要、前置条件及reports证据；客户端明确OS/ABI、签名及已验范围，多ABI如实登记。release是交付用途，不等同编译模式、签名或自动获得资格。
执行前核对工具真实输出；旧debug输出先停用，不能因旧脚本仍在写入而重建目录或改存release。旧 packages/history/artifacts/releases/根clients/offline-packs 留待用户人工整理，不自动删除或迁移，历史内部构建输出不当作新增交付入口。本次同步不声称构建器已适配。人工公共配置目标位置为 deploy/config，旧配置仍在原位；工具在 build-tools，技能维护源在 deploy/skills。
用户已确认的目标、origin、架构、源码来源和范围不反复问；按请求的里程碑完成整批验证，不每小步停下。源码构建允许公开依赖/基镜像，保留原env/锁文件和实际来源记录，不擅自拓展CVE整改或依赖升级。
打包按deploy/AGENTS.md第6节执行：编译/复用、组包、材料完整性校验、输出release包；不准备测试环境，不将安装/运行测试作为出包条件。打包完成不等于目标已安装或媒体验收通过。下文实际部署与验收操作仅适用另行要求的部署任务，不属于打包流程。
离线包使用包内 `INSTALL.md` 的实测入口，不套用根级在线模板或临时联网补包。客户端用目标新CA公开根，不用测试VM CA、不带私钥。不因打包/本地归并擅自SSH、停止、删除或切换任何服务器；破坏性目标操作仍须下文精确二次确认。

## 1. 首先询问部署选择

### 客户端入口配置（与服务端监听配置分离）

- Electron MSI和Android APK仅以工作区`deploy/config/client.env`为入口和发布版本来源，包含`SITE_DOMAIN`、`SITE_SCHEME`、`SITE_PORT`、`CLIENT_VERSION`。先读取已确认值；有效时复用，不重复询问，不把实例地址或版本抄成本技能通用默认值。
- 配置填写客户端可达的外层IP/域名和端口，不从`target.env`、服务端`.env`、旧`deploy/client.env`、进程环境或源码历史默认值覆盖/回退；缺失或无效时先修配置，不能继续打包。
- CLIENT_VERSION是唯一发布版本来源，Electron产品版本与Android versionName共用原值。Android versionCode自动按major×1000+minor×100+patch转换，如1.0.19对应1019；minor限0..9、patch限0..99，越界拒绝Android构建。不自动递增，不读取历史证据、时间计数或release-version.json。旧时间计数APK覆盖升级可能失败，提示但不阻止编译，不自动卸载或清数据。
- `build-tools/clients/build-clients.cjs`已恢复四项配置读取及候选构建编排，先执行--check。WiX从WIX/bin、WIX便携目录、PATH及默认v3安装目录识别，不因默认目录不存在就要求重装。预检查通过不证明真实编译、签名或安装通过，不绕过统一入口和锁。
- 服务端无固定IP模式只让页面/信令跟随请求入口，不负责客户端首次寻址。接受浏览器证书告警不等于Electron/Android自动接受证书；分别检查限定信任策略，不全局关闭证书校验。
- 构建与签名步骤见[客户端参考](references/arm-clients.md)；只更新文档不触发构建、安装、服务器操作或占用版本。

实际部署前先询问以下项目。用户本次已明确的值直接复述确认，只补问缺项，不从历史环境或本机 `.env` 代替用户决定。仅编写交付文档或更新技能时，不要求SSH账号或清理选择，也不连接服务器；缺失的规模、拓扑或单价列为待确认，先形成带假设的草案：

| 必问项 | 需要确认的内容 |
|---|---|
| 入口方式 | **域名还是 IP？** 具体域名/IP、HTTP/HTTPS、端口；公网/内网、直连或代理/转发；页面和 Jitsi 是否同 origin |
| 部署来源 | **从当前源码构建，还是拉取网上已发布 Docker 镜像？** 源码版本/分支，或仓库、tag/digest、访问权限 |
| 服务器架构 | **x86_64（amd64）还是 ARM64（aarch64）？** 不清楚可在授权连接后检测，不能猜 |
| 部署模式 | **全量部署（删除本项目旧有全部资源和数据后重新安装）**，还是**重新部署（仅更新修改部分，保留数据及未变服务）**？不能用“全栈”代替此选择 |
| 目标主机 | SSH 主机/端口/账号、操作系统、部署目录 |
| 服务范围 | 全栈、仅业务 Web/API，还是指定服务？是否复用已有 Jitsi/网关？客户端是否需要另外打包？ |

域名模式补问 DNS、证书来源/签发方式、国内云接入备案条件；IP 模式补问可信 IP 证书或限定自签信任方案。HTTP 仅限用户明确接受的测试环境，说明普通浏览器媒体 API 不可用及传输风险，不能默认降级 HTTP。

**首次响应示例（尚未给参数时）：**
> 本次用域名还是 IP 访问？从当前源码构建还是拉取已发布 Docker 镜像？服务器是 x86_64 还是 ARM64？部署模式选“全量部署（删除本项目旧所有）”还是“重新部署（仅更新修改部分）”？另请提供目标主机、系统和服务范围。我会列出服务、坑和补丁方案后执行。

使用提问工具时可分组询问；不得自行选中历史服务器、镜像仓库或旧安装包。

### 部署模式与全量删除二次确认

- **全量部署（删除旧所有）**：删除目标实例的旧CloudMeet/Jitsi服务及其专属数据库、会标、配置、密钥、证书和项目卷，再全新安装。首次选择仅确定部署意图，**不是立即删除的最终授权**；即使用户已说“全新安装直接清理”，执行删除前也必须完成下面一次集中二次确认，不逐项重复提问。
- **重新部署（更新修改部分）**：只替换变更代码、产物、镜像和必要配置，保留数据、秘密、CA/证书及未变服务，执行最小范围更新。“全栈更新”不等于删数据；仅说“全新安装”但未说明清理语义时，首次澄清选项即可。
- 部署模式与“全栈/部分服务”是独立维度。先只读识别目标实例、目录、Compose项目及专属资源；在任何停止旧服务或删除动作前，集中展示**目标服务器、实例、将删除的目录/容器/卷及数据类别、保留对象、备份位置与实际状态、停机及数据丢失风险**，请求用户明确二次确认。未回复、含糊回复或备份尚未完成，不算已确认清理。
- 二次确认示例：“即将对 <服务器>/<实例> 执行全量重置，删除以下旧项目资源及数据库、会标、密钥和证书；备份状态为 <实际状态>，保留 <对象>。数据无法直接撤销恢复，旧客户端可能失去信任。请回复‘确认全量清理 <服务器>/<实例>’后执行。”不得将示例回复当作用户实际确认。
- 获得明确二次确认后，按展示清单执行，不再逐个询问数据库/证书删除权限。清理范围、目标或备份方案发生实质变化时，先展示变更并重新确认，不沿用旧确认覆盖新增危险操作。
- 授权不包括其他服务器、无关业务、共享网关/卷/证书、全局镜像缓存或Docker系统。仅在资源归属不明、共享依赖、实际目标不符或操作超出授权时暂停询问新增范围。
- 默认先在清理范围外保留权限受限的一致性备份并告知位置；用户明确不备份或要求一并删除项目备份时，不暗中保留，但须在二次确认中突出“无可用备份，旧数据可能永久丢失”。备份失败且方案依赖它时报告阻塞。旧CA删除后旧客户端信任会失效，应告知并为新包配置新CA信任。

## 2. 探测并生成本次参数清单

定位工作区，阅读根 `AGENTS.md`、Web `AGENTS.md` 及本次相关配置。既有环境指令用于保护原服务；用户选择新环境不等于授权改原环境。配置冲突先解释并确认，源码候选使用独立配置/暂存目录，不覆写用户原文件。

经授权连接后只读检查系统、`uname -m`、Docker/Compose、磁盘/内存、端口占用、当前服务/挂载、活跃会议、路由和 DNS/TLS。核实 SSH 主机指纹，不跳过校验。若用户所选架构与实机不符，停止并确认调整。

输出脱敏部署清单（后续命令只能使用本清单的值，不拼入历史地址）：

```yaml
target: { ssh_host: <主机>, ssh_port: <端口>, os: <系统>, arch: <amd64|aarch64> }
access: { mode: <domain|ip>, scheme: <https|http>, host: <域名或IP>, port: <端口> }
public_origin: <scheme://host:port，省略默认端口>
jitsi_origin: <明确的origin，通常与public_origin相同>
source_mode: <source|registry>
deployment_mode: <full-reset|incremental>
cleanup_scope: <全量模式下目标实例的专属资源；增量模式为none>
release: <源码版本或每服务镜像digest>
deploy_dir: <部署目录>
compose_project: <本次项目名>
services: <本次部署服务、复用服务、排除服务>
artifact_usage: release # 仅合格交付；未完成候选留Actions，不填本地交付路径
artifact_arch: <产物自身架构，不从服务器架构推断客户端架构>
actual_output: <核对当前工具后的实际路径，不能假称已迁移>
```

秘密不放进清单/聊天/客户端/镜像。不要打印完整 `.env`、`docker inspect` 或带秘密的 Compose 展开结果，校验优先 `config --quiet`。

## 3. 先解释“会部署什么”，再请求确认

阅读 [服务、坑与补丁清单](references/services-and-patches.md)，按实际 Compose 映射服务名，向用户逐项列出：

| 服务 | 作用 | 本次动作（新建/更新/复用/跳过） | 来源及架构 | 已知坑 | 拟打补丁及适用条件 | 验证方法 |
|---|---|---|---|---|---|---|
| gateway | TLS及统一路由 | 待确定 | 待确定 | 端口/证书/代理 | 按条件选择 | 证书及路由 |
| app-web | 业务页面 | 待确定 | 待确定 | 旧资源/跨域/WebView语法 | 按条件选择 | 新资源及iframe |
| api | 业务与主持人JWT | 待确定 | 待确定 | 持久化/JWT域/权限 | 按条件选择 | health及接口 |
| jitsi-web | 会议页面和信令入口 | 待确定 | 待确定 | 品牌CSS/信令协议 | 按条件选择 | 配置/信令 |
| prosody | XMPP及房间角色 | 待确定 | 待确定 | 目录属主/插件加载 | 按条件选择 | 登录和角色 |
| jicofo | 会议协调和桥选择 | 待确定 | 待确定 | 自动授予主持人/端口 | 按条件选择 | 角色及发现JVB |
| jvb | 多方媒体转发 | 待确定 | 待确定 | NAT/UDP/架构/DTLS | 按条件选择 | 真实媒体 |

上述是逻辑服务名，不是可直接执行的 Compose 服务名。全栈常见七个服务；复用外部 Jitsi 时只部署需要的业务/网关服务。宿主已有网关可不新增容器。TURN、录制、VPN/FRP、Electron/Android 不是默认新增服务，确需时单独确认范围、依赖和验收。

补丁必须逐项标明“已包含/本次应用/不适用/待确认”、理由、来源、目标文件、持久化方式、回滚点及测试。不能把历史补丁全打上，也不能把镜像自带功能重复补丁。提交预计中断范围、备份回滚方案和验收清单；全量清理须单独满足上述集中二次确认门禁，不能以一般方案同意或首次选择代替。确认后不再逐项重复索取相同权限。

## 4. 按选择执行源码或镜像路线

### A. 源码路线

1. 记录相关子项目 commit/dirty 状态，测试并构建本次候选：API 通常 `mvn -B test package`；Web `npm run build` 后执行现有 WebView 语法检查。构建变量来自本次入口选择，保留原 `.env`，检查生成 JS 不含错误环境的有效 iframe origin。
2. “从当前源码构建”覆盖本次服务范围内的工作区项目：全栈时包括业务Web/API及Jitsi Web、Jicofo、JVB、Prosody。允许使用发布的依赖包、工具和基础运行时镜像，不要求编译全部传递依赖；不得静默用官方预构建应用镜像替换这些项目。记录每组件实际commit或源码归档摘要、版本基线、构建测试、产物摘要及运行时身份。用户已确认stable版本和范围时沿用，不重复询问；仅具体缺少源码/工具链才报告阻塞。混合来源须由用户明确批准并逐组件登记。
3. Java JAR/静态资源可在开发机构建，容器内运行的原生依赖/基础镜像必须与目标架构一致。小内存主机不默认现场跑 Maven/npm。
4. 为新环境组装匹配架构镜像或采用已确认的产物挂载方式；独立 staging、SHA256、发布清单，旧包不能冒充新版本。

### B. 已发布镜像路线

1. 先读 [GHCR 镜像清单与运行契约](references/ghcr-images.md)。已发布七个 `ghcr.io/stevenzxs/cloudmeet-*` 候选镜像；用户明确“使用这些镜像/GHCR这批镜像”时沿用该清单，不重复索取仓库/版本。未指定批次时提出该候选供确认，不擅自作为所有环境默认版本。其他仓库仍需确认可信来源、tag/digest及权限，不索取聊天令牌。
2. 本批仅支持 `linux/amd64`；**ARM64 后续单独处理**，本次不构建、不补齐、不模拟。目标为ARM64时报告该批不适用，等待后续专项方案。部署前核对每项远端平台和digest，以完整 `仓库@sha256:…` 锁定身份，不能只改统一JITSI_IMAGE_REPO拼接镜像名。
3. 使用镜像内置产物：纯镜像路线不运行Maven/npm/docker build，不拉源码重编译。API必须去掉旧command和宿主app.jar挂载；业务Web去掉旧dist/nginx.conf覆盖，只保留所需数据挂载。按引用文档渲染独立配置并检查最终Compose，不能只换image就启动。
4. 核对镜像内是否已含品牌、权限、HTTP等补丁；外置初始化、Caddyfile、持久补丁、秘密和数据目录仍按本次入口准备。必须修改镜像内容时优先受支持持久挂载；需派生镜像则解释并获准，不能暗中切源码路线。
5. 拉取全部所需镜像并核对实际平台/身份后才切换服务。匿名manifest可读不等于完整层拉取；login成功不等于write权限；OCI index、平台manifest、config和engine Id分别记录，不跨类型误比。无匹配镜像/权限/补丁支持时报告具体阻塞，不擅自重编译、跨架构模拟或替换来源。发布/公开访问不等于组合运行、媒体验收或安全放行。

### 两条路线共同要求

- 根据本次参数渲染独立 Compose/配置。不能直接把仓库模板里的旧 IP、端口、固定 image tag 或旧目录当成本次配置。增量保留秘密；全量重置清理已授权范围后生成新秘密及CA，不误用其他环境秘密。
- 按方案一致性备份SQLite、旧配置、镜像/产物。增量保留数据与证书卷；全量仅删除已识别的项目专属资源及卷，不套用无范围的`down -v`或递归删除。先校验新配置/镜像再停旧服务并清理，避免清空后才发现无法部署。
- 重启会议栈/网关前确认会议及 endpoints 空闲或获准维护窗口。只更新目标服务，不连带重启共享服务。
- bind mount 静态发布、挂载 JAR 更新、COPY 镜像更新各用对应策略。`restart` 不替换 COPY 镜像内容；重新 build 也不适用于纯拉取路线。
- 禁止全局 prune、`down -v`、全局防火墙清空/网桥删除、全局证书 bypass；不得影响其他业务。错误时停止依赖步骤，说明并按批准方案回滚，不扩大操作范围。回滚后重新验证受影响服务、数据兼容、health/关键接口和会议恢复，容器启动不能代替回滚验收。

## 5. 部署中逐服务报告进度

维护全服务状态表，状态为 `待处理/检查中/准备中/部署中/验证中/已通过/失败/阻塞/复用已验证/跳过`。每个服务开始、阶段完成、失败时输出一次简短更新，不只输出最后“已启动”。

```text
[3/7][prosody][部署中] 已核对目标架构与镜像摘要，正在安装持久化角色插件。
[3/7][prosody][验证中] 配置检查通过，正在确认XMPP登录与实际模块加载。
[3/7][prosody][已通过] 模块加载及focus/jvb登录通过；真实主持人角色等待联合验收。
```

示例不是执行证据。实际输出必须根据工具结果，不虚构百分比/成功。并行启动时也分别报告每个服务状态，不能把 Compose 一次成功当全部服务通过。失败要指出对后续服务的阻塞及下一步，不让依赖验证继续报绿。

服务级检查和联合验收分两列记录：示例中的Prosody“已通过”仅指模块/登录检查，角色和真实会议仍为未验证，最终不能合并成全部通过。

## 6. 部署完成后逐项给关键测试结果

用本次 `public_origin` 及实际服务名执行，报告 `通过/失败/阻塞/未验证/不适用`，每项含预期、实际、证据位置/命令退出码。只部署部分服务也要说明最小回归范围，不能沿用旧报告结果。

| 测试 | 关键检查 |
|---|---|
| 产物及架构 | 实际镜像digest/架构、产物SHA256匹配本次清单；容器无重启循环 |
| 业务Web/API | 外网 `/cm/desktop` 与新资源；`/mapi/actuator/health` UP；变更接口无破坏性回归 |
| origin与TLS | 实际页面、external_api及iframe scheme/host/port；证书链或获准精确信任有效，不能用 `-k` 验收 |
| 信令 | 当前模式的WebSocket真实握手/会话或BOSH会话；配置返回200不等于信令通过 |
| 主题及补丁 | CSS资源hash、品牌与角色插件实际加载、每项补丁的专项测试 |
| 权限 | 主持人OWNER、普通参会者PARTICIPANT；不能人人自动主持 |
| 真实媒体 | 至少三端或关闭P2P走JVB；双向音视频、selected ICE/媒体统计、共享、退会和重连；UDP监听不等于可用 |
| 持久化和隔离 | 数据/证书挂载正确；非目标容器身份/启动时间未变；不做未经批准的破坏性重启测试 |
| 可选客户端 | 入口配置、manifest、摘要、签名；MSI/APK安装升级及VPN实测独立列结果 |

HTTP模式普通浏览器缺安全上下文不当应用故障；仅在明确批准且实现限定例外的Electron/Android上验媒体。缺设备/网络/权限时标未验证，说明剩余风险，不宣称生产就绪。

## 7. 最终交付与历史参考

本批Docker包不包含宿主操作系统，不要求麒麟ISO。包级安装资格不作为编译打包门禁；宿主兼容性前提写入INSTALL，不能仅凭发行版名称宣称兼容。具体材料缺失/已知不兼容应修复或明确报告，不虚构已适配。

“打包release”仅执行第6节流程，复用适用镜像，组装配置/补丁/依赖/安装工具和说明，校验最终归档及下载副本摘要，报告实际release路径。无安装/运行测试环节。现有READY拒绝逻辑需单独修复，不手改状态或以文档宣称已完成。本文不表示现有工具已适配。

交付：本次入口/架构/源码或镜像来源；逐服务动作和最终状态；**实际打过哪些补丁、哪些跳过及原因**；关键测试表和证据；备份与回滚位置；失败/未验项及下一步。构建成功、部署成功、会议验收通过分别表述。
